# نتیجهٔ بررسی انتشار — ۲۰۲۶-۱۱-۱۹

این بررسی روی تغییرات فعلیِ ثبت‌نشده در Git انجام شد. محیط اصلی تغییر نکرد و
آزمون‌های نوشتن اطلاعات، فقط روی دیتابیس موقت اجرا شدند. پیامک واقعی ارسال نشد.

## نتیجه

خروجی فرانت‌اند برای انتشار روی Nginx آماده است. مانع نرم‌افزاری در بررسی‌های زیر
پیدا نشد؛ این نتیجه تضمین عملکرد زیرساخت یا تأیید قالب‌ها توسط SMS.ir نیست.

| بررسی | نتیجه |
|---|---|
| آزمون‌های Django با SQLite موقت و پیامک شبیه‌سازی‌شده | ۸۱ موفق |
| آزمون‌های فرانت‌اند | ۲۱ موفق |
| مرورگر، ۸ سناریو در دسکتاپ، تبلت و موبایل | ۲۴ موفق |
| بررسی TypeScript، lint و ساخت production | موفق |
| بررسی تغییرات مدل‌ها | migration جدید لازم نیست |
| شروع تازهٔ production، collectstatic، HTML ادمین و CSS با WhiteNoise | موفق در آزمون جداگانه |
| آدرس API داخل خروجی نهایی | `/api`؛ آدرس توسعه و IP داخلی وارد بسته نشده‌اند |
| واحد پول داخل خروجی | تومان؛ در `.env.production` عمومی تثبیت شد |
| ورود و داشبورد از خود فایل‌های production | موفق با حساب آزمایشی و API موقت هم‌دامنه |
| مدل سه‌بعدی در خروجی production | لمس: اجزا ← یکپارچه ← اجزا؛ اسکرول، نما را عوض نکرد |
| پیگیری عمومی از خروجی production | موفق با سفارش موقت و فیلدهای عمومی |

سناریوهای مرورگر شامل ورود، تمدید و انقضای نشست، نقش‌های مدیر/پذیرش/تعمیرکار،
ثبت سفارش، مشتری و دستگاه، گردش وضعیت، پرداخت، تاریخچه و پیگیری عمومی بودند.

## بستهٔ آمادهٔ فرانت‌اند

- فایل: `artifacts/repairdesk-web-2026-11-19-verified.tar.gz`
- شامل ۶۲ فایل از `frontend/dist`؛ فایل‌های داخل آرشیو با خروجی build مقایسه شدند.
- `index.html` در ریشهٔ آرشیو است و پوشهٔ اضافهٔ `dist` ندارد.
- فایل‌های ENV، دیتابیس، لاگ مرورگر و مدارک ارائه داخل آرشیو نیستند.
- در سرویس فعلی، مقصد انتشار `/usr/share/nginx/html/repairdesk` است.
- این بسته فقط ظاهر سایت را منتشر می‌کند؛ Django یا Worker پیامک را تغییر نمی‌دهد.
- فایل SHA256 کنار آرشیو و جزئیات build در `artifacts/release-check-2026-11-19.json` است.

SHA256:

```text
3de9deabefe7a8443ecf9e066ef1088f286fe3106656a54ca374d57ba1dd7121
```

فایل‌های جدید مدل، `frontend/src/styles/landing.css` و `frontend/.env.production`
باید همراه بقیهٔ تغییرات فرانت‌اند به Git اضافه شوند. صرفاً push کردن Django، خروجی
React را روی دیسک سرویس Nginx فعلی جایگزین نمی‌کند. برای بازگشت، خروجی قبلی Nginx
را پیش از جایگزینی نگه دارید. تنظیمات فعلی Nginx نیاز به تغییر برای این طراحی ندارند.

## موارد وابسته به محیط اصلی

- خواندن صفحات فعلی `https://suncitymobile.ir/`، `/login`، `/track`، `/admin/login/`
  و CSS ادمین با پاسخ ۲۰۰ و HTTPS معتبر انجام شد. API پیگیری برای کد ناموجود
  پاسخ ۴۰۴ JSON داد. این‌ها وضعیت نسخهٔ قبلیِ مستقر را بررسی می‌کنند.
- تست‌ها با Python 3.11.9 و Django 5.2.16 روی Windows انجام شدند؛ اجرای همین
  نسخه روی MySQL اصلی، Python 3.12 و Gunicorn لینوکسی در این بررسی انجام نشده است.
- `check --deploy` با متغیرهای آزمایشی خطا نداشت. دو هشدار عمدی HSTS مربوط به
  subdomains/preload باقی‌اند؛ بدون تأیید HTTPS همهٔ زیردامنه‌ها فعال نشوند.
- آزمون WhiteNoise از سورس رسمی 6.12.0 موجود در محیط محلی استفاده کرد؛ نصب
  `requirements.txt` همچنان بخشی از build واقعی سرویس Django است.
- Docker Engine محلی فعال نبود؛ ایمیج‌های نمونه و syntax واقعی Nginx اجرا نشدند.
- تغییر قبلی SMS.ir، مقدار `LINK` را به صورت `track?code=...` می‌فرستد. انتشار آن
  باید با قالب‌های تأییدشده‌ای هماهنگ باشد که پیشوند ثابت
  `https://suncitymobile.ir/#LINK#` دارند. ارسال واقعی و فعال بودن Worker تأیید نشدند.
- آدرس فیزیکی تعمیرگاه هنوز ارائه نشده و در سایت نمایش داده نمی‌شود.
