# نتیجه بررسی فرانت‌اند

تاریخ: ۲۰۲۶/۰۸/۲۹ — Windows، Node 22.15.1، pnpm 11.19.0 و Chrome نصب‌شده.

## نتیجه نهایی

| بررسی | نتیجه |
| --- | --- |
| نصب dependencyها با lockfile | موفق؛ ۳۴ dependency مستقیم، metadata و نسخه نصب‌شده هماهنگ |
| `pnpm typecheck` | موفق؛ TypeScript strict |
| `pnpm lint` | موفق؛ صفر warning با `--max-warnings 0` |
| `pnpm build` | موفق؛ خروجی production در `dist/` |
| `pnpm test` | ۲۰ تست موفق در ۳ فایل |
| `pnpm test:e2e` | ۲۴ تست موفق، بدون retry، حدود ۲٫۵ دقیقه |
| `pnpm test:live` | یک تست skip؛ credential محیط اصلی ارائه نشده |
| Django `manage.py check` | بدون مسئله |
| بررسی دستی مرورگر | انجام شد؛ عمومی و پنل متصل به API موقت |

E2Eها خود کد Django را با migrationهای واقعی، SQLite موقت و حساب‌های صریحاً آزمایشی اجرا می‌کنند. هیچ جدول یا داده‌ای در پایگاه اصلی تغییر نکرده است. تست‌های واحد فقط برای جداسازی رفتار client، پاسخ fetch آزمایشی دارند؛ محصول هیچ mock API یا داده نمایشی دائمی ندارد.

## پوشش مرورگر

اندازه‌های 1440×1000، 768×1024 و 390×844. هر هشت سناریوی زیر در هر سه اندازه اجرا شده‌اند:

1. Landing، reduced motion بدون Canvas، فرم نامعتبر، ناوبری صفحه‌کلید و 404.
2. پیگیری معتبر با trim/uppercase، کد ناموجود، پاسخ عمومی محدود و عدم ارسال Authorization.
3. مسیر محافظت‌شده، ورود مدیر، refresh پس از reload، dashboard، فیلتر URL، جست‌وجو، pagination، خروج و عدم بارگذاری Three.js در مسیر پنل.
4. ثبت سریع مشتری/دستگاه/سفارش، transition مجاز، رد transition غیرمجاز توسط Django، دریافت با زمان سرور و ISO دستی، پرداخت و لغو پرداخت با paid_at خودکار، history و وضعیت نهایی.
5. پرونده مشتری، افزودن دستگاه، ثبت و ویرایش کارمند، غیرفعال‌کردن و عدم ارسال password خالی.
6. منوی پذیرش و تعمیرکار، منوی موبایل و رد مستقیم مسیرهای غیرمجاز.
7. انقضای واقعی access هشت‌ثانیه‌ای، پاسخ 401، refresh و retry؛ شکست refresh نامعتبر و حذف نشست.
8. ثبت با مشتری و دستگاه موجود؛ جست‌وجوی مدل آماده و ثبت دستگاه جدید برای مشتری موجود.

همه تست‌های E2E نبود خطای JavaScript مدیریت‌نشده و نبود پاسخ 5xx را نیز بررسی می‌کنند. گزارش HTML در `playwright-report/` و تصاویر Landing/Dashboard در `test-results/visual/` تولید می‌شوند؛ این فایل‌های تولیدی در Git قرار نمی‌گیرند.

بررسی دستی شامل Landing سه‌بعدی production، لینک بخش خدمات و cleanup Canvas خارج از viewport، فرم‌های پیگیری/ورود در موبایل و تبلت، خطاها و فوکوس، مسیر محافظت‌شده، ورود به پنل موقت، داشبورد، فهرست سفارش‌ها و خروج بود. تصاویر سه اندازه بازبینی شدند و overflow افقی در مسیرهای آزمون دیده نشد.

## کنتراست و دسترس‌پذیری

نسبت کنتراست زوج‌رنگ‌های اصلی محاسبه شد: متن اصلی 15.97:1، متن فرعی 5.49:1، دکمه teal با متن سفید 5.12:1، placeholder فرم 5.20:1 و متن هفت وضعیت بین 5.44:1 و 7.13:1. این بررسی شامل ممیزی جامع WCAG یا آزمون با screen reader واقعی نیست. label و خطاهای فرم، focus، RTL، reduced motion و تعامل صفحه‌کلید بررسی شده‌اند؛ dialogها از Radix استفاده می‌کنند.

## هشدارها و محدودیت‌ها

- در Console نمای سه‌بعدی، هشدار upstream مربوط به deprecated شدن `THREE.Clock` دیده می‌شود؛ R3F فعلی هنوز آن را می‌سازد. رندر موفق است و هشدار پنهان نشده است. Console خروجی production خطای runtime نداشت.
- هنگام اجرای ابزارها، هشدار محیطی `NO_COLOR/FORCE_COLOR` و در یک Build پیام اندازه‌گیری زمان pluginهای Rolldown دیده شد؛ Lint صفر warning و Build exit code صفر دارند.
- یک گیر اولیه از cache داخل watcher توسعه و یک گیر از preconnect مرورگر در WSGI تک‌ریسمانی تست پیدا شد. cacheها جدا/مستثنا شدند و سرور fixture threaded شد؛ مجموعه کامل پس از این اصلاح‌ها موفق اجرا شد.
- حساب واقعی، داده MySQL اصلی، شبکه production، مرورگر Safari/Firefox و دستگاه فیزیکی آزموده نشده‌اند. اتصال محیط اصلی باید پیش از انتشار بررسی شود.
- نام/تماس/آدرس/ساعت کاری/خدمات و واحد پول باید توسط تعمیرگاه تأیید و تنظیم شوند.
- ریسک‌های امنیتی و نواقص API در [backend-gaps.md](backend-gaps.md) با فایل و خط ثبت شده‌اند؛ بک‌اند در این کار اصلاح نشده است.

تغییرات قبلی Git حفظ شدند؛ diff سه فایل tracked بک‌اند همان ۵۸ خط افزوده و ۶ خط حذف‌شده اولیه باقی ماند. فایل‌های این پیاده‌سازی در `frontend/` هستند.
